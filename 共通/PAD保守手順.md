# PAD保守運用手順

## 基本手順

```text
① 画面変更・エラーを確認
        ↓
② before / after画面を保存
        ↓
③ 現在のPADフローを保存
        ↓
④ エラー内容を確認
        ↓
⑤ GitHub Copilotで原因分析
        ↓
⑥ Copilotの修正案を人間が確認
        ↓
⑦ 人間がPADを修正
        ↓
⑧ テスト
        ↓
⑨ 手順書・テスト記録・変更履歴を更新
        ↓
⑩ GitHubへ保存
```

## AIに任せること

- before / after画面、PADフロー、エラーの比較
- 影響する可能性があるアクションの特定
- 原因の整理と、必要最小限の修正案の提案
- 修正後のテスト項目案
- 実施済みの事実に基づく文書更新案

## 人間が行うこと

- AIの分析結果と修正案の確認
- PAD本体の修正
- 修正内容の確認とテスト
- 本番適用の判断と最終承認
- 実際の結果に基づく手順書、テスト記録、変更履歴の更新

## やってはいけないこと

- AIにPAD本体を勝手に変更させること
- AIや未確認の案をそのまま本番適用すること
- テストしていない内容を正常と記録すること
- 業務仕様、PADフロー、テスト結果、変更履歴を推測で作ること
- UI要素や安定したセレクターの確認なしに座標クリックへ変更すること

## 機密情報の扱い

パスワード、アクセストークン、秘密鍵、証明書秘密情報、不要な顧客情報を保存しない。スクリーンショットやフロー記録に機密情報が含まれる場合はマスキングし、保存が必要か人間が確認する。

## Gitへの保存

変更内容を人間が確認してから、必要に応じて次の基本操作で保存する。

```text
git status
git add .
git commit -m "変更内容を記録"
git push
```

Gitの目的は変更履歴、差分、過去状態の確認と誤変更時の復旧である。ブランチ、Pull Request、CI/CDは必須としない。
