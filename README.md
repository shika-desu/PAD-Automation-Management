# PAD保守運用

Power Automate for desktop（PAD）の業務自動化フローを、安全かつ簡単に保守運用するための管理基盤です。画面変更時の調査、影響箇所の特定、修正案、テスト、関連文書の更新を、事実と推測を分けて記録します。

## 管理対象

- PADフローの記録
- 画面変更前後のスクリーンショット
- 操作手順書
- テスト記録
- 変更履歴
- 共通の保守手順

## フォルダ構成

- `.github/`: Copilotの共通ルールと再利用プロンプト
- `業務A/`: 実際の業務名が決まるまで使うサンプル業務テンプレート
- `共通/`: 業務をまたいで使う保守手順

## 画面変更時の基本手順

1. `業務A/画面変更/` に `before.png` と `after.png` を保存する。
2. 現在のPADフローとエラーメッセージを記録する。
3. Copilotで画面、フロー、エラーを比較し、影響アクションと最小限の修正案を整理する。
4. 人間が案を確認し、PAD本体を修正する。
5. 人間がテストし、結果を `テスト.md` に記録する。
6. 必要に応じて `手順書.md` と `変更履歴.md` を更新する。

## GitHub Copilotの利用

`.github/prompts/pad-repair.prompt.md` は画面変更の原因分析に、`pad-document-update.prompt.md` は実施済みの修正とテストに基づく文書更新案に使います。未確認の内容は推測・提案として扱い、実施済みとして記録しません。

## 役割分担と安全上の注意

Copilotは分析、比較、影響箇所の特定、修正案、テスト項目案を担当します。人間は分析結果の確認、PADの修正、テスト、本番適用判断、最終承認を担当します。CopilotにPADの直接変更や本番適用をさせないでください。パスワード、トークン、秘密鍵、証明書秘密情報、不要な顧客情報は保存せず、スクリーンショットは必要に応じてマスキングしてください。

## Gitの基本操作

```text
git status
git add .
git commit -m "変更内容を記録"
git push
```

Gitは変更履歴、差分、過去状態の確認と誤変更からの復旧に使います。ブランチ、Pull Request、CI/CDは必須としません。
